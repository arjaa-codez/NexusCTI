## 4. Check 3: Output and Failure Accounting Validation (PASS)

### 4.1 Evaluation of Synthetic Outcome Fixtures
To ensure the 30-case Task B scoring schema handles all execution edge cases deterministically without ambiguity, 8 synthetic fixtures representing all possible system outputs were evaluated under the frozen protocol rules:

```python
CLOSED_SET_CANDIDATES = {"actor_apt28", "actor_apt29", "actor_lazarus", "actor_sandworm", "actor_volt_typhoon", "actor_fin7"}

def score_task_b_case(item: Dict[str, Any]) -> str:
    res = item["mock_result"]
    status = res.get("execution_status")
    verdict = res.get("verdict")
    candidate = res.get("top_candidate")
    
    # Rule 1: Operational failure cannot be credited as an abstention
    if status != "SUCCESS":
        return "EXECUTION_FAILURE"
        
    # Rule 2: Unrecognized actor without abstention is an execution failure
    if candidate not in CLOSED_SET_CANDIDATES and verdict != "INCONCLUSIVE":
        return "EXECUTION_FAILURE"
        
    # Rule 3: Valid calibrated abstention
    if verdict == "INCONCLUSIVE":
        return "PROPER_ABSTENTION"
        
    # Rule 4: Confident attribution to closed-set candidate is False Attribution
    if verdict in {"PROBABLE", "HIGH_CONFIDENCE", "CONFIRMED"} and candidate in CLOSED_SET_CANDIDATES:
        return "FALSE_ATTRIBUTION"
        
    return "EXECUTION_FAILURE"
```
